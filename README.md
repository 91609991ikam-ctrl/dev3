# 🚶 さんぽビンゴ

散歩を少しだけ楽しくするための、3×3 のビンゴアプリ。

毎週月曜に **9つのゆるいミッション** が届きます。「黄色い食べもの」「自分の影」「はじめて通る道」くらいの、
歩いていれば数分で見つかる難易度です。見つけたら写真を撮ってマスに紐づけるとクリア。
タテ・ヨコ・ナナメが揃うとビンゴになります。

## できること

- **毎週9マスの自動更新** — 週番号から決まるので、月曜になると勝手に新しいカードになる
- **写真でクリア** — その場でカメラ、または保存済みの写真から選ぶ
- **ビンゴ判定** — 8ライン。揃うとお祝いが出て、そのラインが金色になる
- **引き直し** — どうしても無理なミッションは、週に1回だけ引き直せる
- **アルバム** — 週ごとのフォルダにまとまる。開くとその週のビンゴカードが
  そのまま並び、撮れなかったマスも当時のミッション名で残る
- **書き出し** — 撮った写真をZIPでまとめて保存（週ごとの書き出しも可）。
  スマホでは写真を選んで共有シートに送れる（写真アプリやクラウドに直接しまえる）
- **完全オフライン** — 写真も進捗も端末内（IndexedDB）だけ。サーバーもアカウントも不要
- **ホーム画面に追加**（PWA）して、電波のない場所でも使える

## ミッションのバリエーション

17カテゴリ × 18個 = **306ミッション**。

いろ / かたち / いきもの / しょくぶつ / そら・てんき / まちかど / もじ・すうじ / のりもの /
ひかりとかげ / ちいさな発見 / くらしのあと / たべもの / 五感 / うごき / なつかしい / すきま・きわ /
へんなもの

抽選は次のようになっています。

- 9マスのジャンルは**毎週くじ引き**。重複を避けていないので、同じジャンルが
  2〜4マス並ぶ週もあれば、まったく出ないジャンルもある（1ジャンルあたり週0.53マス）
- ミッションはカテゴリごとに「シャッフルした山札を1枚ずつめくる」方式。
  同じミッションが戻ってくるまでの目安は「件数 × カテゴリ数 ÷ 9」週（18個・17カテゴリで34週。
  実測で中央値32週、4週以内の再登場は全体の0.5%）
- 週番号だけから決まるので、同じ週なら誰の端末でも同じカードになる

## 使いかた

そのまま `index.html` を開くだけでも動きますが、Service Worker（オフライン対応）を有効にするには
HTTP で配信してください。

```sh
python3 -m http.server 8000
# → http://localhost:8000 をスマホのブラウザで開く
```

GitHub Pages などの静的ホスティングにそのまま置けます（ビルド不要・依存パッケージなし）。

### ホーム画面に追加する（iPhone）

1. **Safari** で公開URLを開く（プライベートブラウズは不可）
2. 下の共有ボタン（□に↑）→ メニューを下にスクロール →「ホーム画面に追加」
3. 名前を確認して「追加」

先に追加してから撮り始めてください。iOSではホーム画面のアプリとSafariで
保存領域が分かれるため、Safariで撮った写真はホーム画面版に引き継がれません。
ホーム画面から起動すると、オフラインでも開けて、写真も消えにくくなります。

アイコンは `icon-180.png`（`apple-touch-icon`）を使います。iOSはSVGを
アイコンとして受け付けないため、PNGを別に用意しています。

Android の Chrome は、メニュー →「アプリをインストール」または
「ホーム画面に追加」で同じことができます。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面の骨組み |
| `styles.css` | 見た目（ライト/ダークモード対応） |
| `missions.js` | ミッションのプール（ここを編集すれば自由に増やせる） |
| `store.js` | IndexedDB への保存（写真・週ごとの状態） |
| `zip.js` | 書き出し用の最小限のZIP生成（無圧縮・依存なし） |
| `app.js` | 週の計算、抽選、ビンゴ判定、画面の描画 |
| `sw.js` / `manifest.json` / `icon.svg` | PWA まわり |
| `tools/bundle.js` | CSS/JSを埋め込んだ単一ファイル版を `dist/` に出力 |

## ミッションを増やす

`missions.js` の配列に足すだけです。1カテゴリの件数を変えても抽選はそのまま動きます。

```js
{ t: 'マスに出す短い名前', h: 'タップしたときに出るゆるいヒント' }
```

追加するときの方針:

- **人が写り込むものは入れない。** 他人、表札、玄関まわり、他人の私物など。
  散歩中にカメラを向けにくいものは、ミッションとしても向いていない
- **写真1枚で何のことか分かるものにする。** 「音がしたほう」のような、
  写真に写らないものが主役のミッションは、あとで見返しても意味が分からない
- **難易度は揃えなくていい。** 抽選は完全にランダムなので、むずかしいマスが
  重なってクリアできない週があってもいい

ミッションを差し替えても、すでに写真を撮ったマスは「撮ったときのミッション」を
表示しつづけます（アルバムの記録も同じ）。

## 写真の書き出し（バックアップ）

写真はブラウザのIndexedDB（端末の中）にしかありません。ブラウザのデータを消したり、
端末を買い替えたりすると失われるので、アルバムタブの「すべてZIPで書き出す」で
ときどき手元に保存しておくのが安全です。

ZIPの中身:

```
2026-09-01_0816_青いもの.jpg      ← 撮影日時_ミッション名
2026-09-01_0817_木もれ日.jpg
ミッション一覧.txt                 ← ファイル名・ミッション・カテゴリ・撮影日時・週の一覧
```

スマホで `navigator.share` が使える環境では「写真アプリなどに送る」も出ます。
こちらは共有シートが開くので、カメラロールやクラウドに直接しまえます。

## 検索よけ

身内で遊ぶ想定なので、検索結果に出ないようにしてあります。

- `index.html` の `<meta name="robots" content="noindex, nofollow">` … これが本体。
  クローラはこのタグを見てインデックスをやめる
- `robots.txt` … `ユーザー名.github.io/リポジトリ名/` 形式（プロジェクトページ）では、
  クローラが読むのはドメイン直下の `/robots.txt` だけなので、このファイルは
  独自ドメインやユーザーページに移したときの保険

なお、これは「検索に出ない」だけで、URLを知っている人は誰でも開けます。
静的サイトなのでパスワードはかけられません。写真は各自の端末の中にしか
残らないので、URLを共有しても他人に写真を見られることはありません。

## 写真の扱いで気をつけていること

- **位置情報を残さない** — 保存時にcanvasを通すのでEXIF（GPS含む）は落ちます。
  縮小に失敗した写真も、JPEGならAPP1〜APP15を削ってから保存します
  （`stripJpegMetadata`）。書き出したZIPを人に渡しても自宅は漏れません
- **消えにくくする** — 起動時に `navigator.storage.persist()` を申請します。
  ブラウザが「勝手に消してよいデータ」として扱わなくなります（許可されるかは
  ブラウザ次第。ホーム画面に追加していると通りやすい）
- **誤操作で消さない** — 写真の削除は2段階。1回目のタップでは確認に変わるだけで、
  5秒放置すると元に戻ります
